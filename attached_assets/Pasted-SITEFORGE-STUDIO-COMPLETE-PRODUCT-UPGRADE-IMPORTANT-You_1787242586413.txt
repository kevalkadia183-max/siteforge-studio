Do not rely only on frontend checks.

IMPLEMENTATION RULES

1. Do not rewrite working systems unnecessarily.
2. Do not remove the existing templates.
3. Do not remove existing ZIP export.
4. Do not weaken receptionist safety policies.
5. Do not expose secrets to frontend code.
6. Do not use browser localStorage as the authoritative database after Phase 1.
7. Do not claim a feature is complete until it has been tested end-to-end.
8. Do not create UI-only placeholders and mark them as working.
9. Do not silently change existing product behavior.
10. Use database migrations for schema changes.
11. Create backups/checkpoints before major migrations.
12. Keep Git as the source of truth.
13. Run typecheck/build/tests after each major phase.
14. If a migration could destroy existing data, STOP and explain the migration strategy before executing it.
15. Preserve existing functionality during migrations.
